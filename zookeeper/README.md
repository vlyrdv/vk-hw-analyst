# Отказоустойчивость с Apache ZooKeeper

Отчёт с результатами экспериментов: [REPORT.pdf](REPORT.pdf).

Ансамбль состоит из трёх серверов ZooKeeper 3.9.6. Два координатора рассчитывают пары навыков из ДЗ № 3. При смене лидера расчёт продолжается с чекпоинта. Получатель результата проверяет эпоху при включённой защите `FENCING=1`.

## Запуск

Нужны Docker Compose и Python 3.10+. Команды выполняются из папки `zookeeper`.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/prepare_data.py
docker compose up -d
.venv/bin/python scripts/run_all.py
```

Сценарий проверяет кворум и эфемерные узлы, затем выполняет два опыта с приостановкой лидера: без защиты и с проверкой эпохи. Журналы сохраняются в `logs/`, результаты — в `results/`.

Для отдельных запусков:

```bash
.venv/bin/python scripts/failover.py --fencing 0 --run my-unsafe
.venv/bin/python scripts/failover.py --fencing 1 --run my-safe
```

Для каждого нового опыта нужно уникальное имя `--run`. Тайм-аут сессии — 10 секунд, приостановка лидера — около 40 секунд. Аргумент `--fencing` задаёт переменную `FENCING` для координаторов.

## Проверка результатов

Проверка сохранённых экспериментов без Docker и установки зависимостей:

```bash
python3 scripts/verify_terminal_evidence.py
```

Проверяются журналы, восстановление с чекпоинта, время смены лидера, число принятых публикаций и полное совпадение CSV с эталоном ДЗ № 3.

## Файлы

- `compose.yaml`, `conf/` — конфигурация трёх серверов.
- `src/coordinator.py` — выбор лидера, расчёт и чекпоинты.
- `src/receiver.py` — публикация результата с проверкой эпохи.
- `src/core.py` — подключение к ZooKeeper и общие функции.
- `src/hw3_*.py` — исходный расчёт из ДЗ № 3.
- `scripts/` — запуск экспериментов и проверка результатов.
- `data/` — сжатые входные данные и эталон ДЗ № 3.
- `logs/`, `results/`, `screenshots/` — журналы, результаты и снимки терминала.

Остановка ансамбля:

```bash
docker compose down
```
